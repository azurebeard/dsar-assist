## A01 — Broken Access Control

**SEC-H-02 — allowlist escape via dot-segment. RESOLVED.** Reported in full in
`WS10-review-phases1-4-2026-08-14.md`. `caseId=".."` resolved to
`/security/cases/searches`, outside the permitted-operations table. Fixed;
14-vector regression test.

**SEC-L-05 — `/auth/logout` accepted a cross-origin POST. RESOLVED.**

**Probed clean:**
- Write authorisation enforced **server-side** in `Workflow._require_write`, not
  by hiding buttons. `DSAR.Auditor` and a role-less principal were both refused
  create-case, create-search, run-estimate and initiate-export.
- Session and origin checks live in one adapter, not per-route.
- No CORS anywhere, and no configuration that adds it.

**Accepted by design, and worth stating plainly:** `/api/case` and
`/api/statistics` take a `case_id` and do not check that the case belongs to the
calling operator. This is deliberate — the token is delegated, so Purview
returns 403 for a case the operator cannot see, and re-implementing that check
locally would be a second, weaker copy of an authority we do not own. The
consequence is that **authorisation is Purview's, entirely.** If Purview's RBAC
is wrong, this tool is wrong with it. That is the correct trade for a control
plane, but it should be said rather than assumed.

## A02 — Cryptographic Failures

Clean.

- Tokens in memory only. `msal.SerializableTokenCache` is banned by a structural
  test that checks both text and AST, so the property cannot be quietly
  downgraded.
- No secret exists: desktop is a public client with PKCE, hosted uses a
  federated credential minted at runtime. `doctor` **fails** if any variable
  ending `_SECRET`, `_PASSWORD`, `_ASSERTION`, `_CERTIFICATE_PATH` or
  `_PRIVATE_KEY` is set.
- Session and flow identifiers are 256-bit `secrets.token_urlsafe`.
- Audit directory forced to `0700` on create *and* when pre-existing.
- `config.json` is refused if group- or world-writable — it selects the Entra
  tenant, so whoever can write it chooses the identity provider.
- Transport: hosted sends HSTS; desktop is `http://localhost` by design, and
  the `__Host-`/`Secure` cookie deviation there is documented rather than assumed.

## A03 — Injection

Clean, and probed rather than reasoned about.

| Surface | Vectors | Result |
|---|---|---|
| KQL | quote break-out, escaped-quote break-out, NUL, CR, LF, clause injection | All refused. Values that cannot be expressed in a phrase are **rejected, never escaped** — KQL has no portable escape for a quote inside a phrase, so escaping would silently change what was searched for |
| OData (`find_users`) | `' or startswith(...)`, `'--`, NUL, 300 chars | Single quotes correctly **doubled** (the only escape OData defines); control characters and over-long values refused |
| URL path | 14 vectors | All refused after SEC-H-02 |
| HTML | subject-controlled values in the rendering path | `textContent` throughout; no `innerHTML` on dynamic values. Server-rendered error pages escape via `_escape` and sit in text context |
| Log | CRLF in a request path | Unmatched routes log the constant `<unmatched>`, never the caller's string |

No SQL exists; `sqlite3` and four other database drivers are banned by AST check.

## A04 — Insecure Design

### OWASP-A04-01 — No rate limiting anywhere. RESOLVED.
**Severity:** Medium
**Finding:** Neither `/auth/login` nor the API had any limit. The plan had
specified *"a per-session, per-search minimum interval returning 429 with
`Retry-After`, so a rogue tab cannot spam Graph on the operator's token"* — it
was never implemented, and nothing noticed because nothing tested for it.
**Why it matters here specifically:** every API call spends the **operator's**
Graph token, and Purview throttles the *account*, not the process. A runaway
browser tab therefore degrades that operator's other tools, and looks
indistinguishable from abuse at the tenant end.
**Reference:** OWASP Top 10 2021: A04 · CWE-770 (Allocation Without Limits)
**Resolution:** `web/limits.py` — fixed-window limiter. `/auth/login` 10/min per
peer; API 120/min per operator; statistics polling floored at 5s per search.
All return 429 with `Retry-After`, and a denied attempt is still recorded so
ignoring a 429 earns no free pass.

### OWASP-A04-02 — An unauthenticated caller could cancel someone else's sign-in. RESOLVED.
**Severity:** Medium
**Finding:** `FlowStore` evicted the oldest entry when full. Each `/auth/login`
allocates one, and the endpoint needs no authentication — so 65 requests pushed
a real operator's in-progress sign-in out of the store. Their callback then
returned "sign-in expired" with no cause they could see.
**Evidence:** probe — *"victim's pending flow after 69 more: EVICTED"*
**Reference:** OWASP Top 10 2021: A04 · CWE-400 (Uncontrolled Resource Consumption)
**Resolution:** the store now **refuses** (`FlowStoreFull` → 429) rather than
evicting. Refusing is the better failure: visible, and it affects the caller
causing it rather than a bystander. The rate limit stops it filling; this is the
backstop for when that is misconfigured.

**Related, accepted:** `SessionStore` still evicts LRU when full at 64. Creating
a session requires completing a sign-in, so this is not reachable
unauthenticated. On a shared hosted instance an authenticated operator could
evict colleagues; noted for the Phase 5 review, where the hosted session model
is in scope.

## A05 — Security Misconfiguration

Clean, and the interesting part was probed.

- **Unhandled exceptions leak nothing.** A handler raising
  `RuntimeError("secret internal detail: /home/ben/.dsar/config.json")` produced
  a **500 with a 21-byte body** — no traceback, no exception type, no path — and
  the security headers were still attached.
- CSP `default-src 'none'`, no `unsafe-inline`, no `unsafe-eval`. Plus COOP,
  CORP, Permissions-Policy, nosniff, DENY, `no-referrer`, `no-store`.
- No debug mode; `server_header=False`; version withheld from `/healthz` in
  hosted mode.
- Static assets are an explicit allowlist, not a directory mount. Traversal
  returns 404.
- Container: non-root uid 10001, read-only root filesystem, `--cap-drop ALL`,
  `no-new-privileges`, no package installer in the image.

## A06 — Vulnerable and Outdated Components

Clean.

- Four declared dependencies; `uv.lock` pins across platform markers and CI
  fails on a stale lock.
- Trivy in CI: **zero fixable High or Critical**. A second non-blocking scan
  reports unfixed findings so they are known rather than suppressed.
- Base images pinned by digest; every GitHub Action SHA-pinned; Dependabot on
  pip, docker and actions.
- This category found a real vulnerability once already: `starlette` 0.52.1 →
  1.6.0 for `CVE-2026-48818` (SSRF and NTLM credential theft via UNC paths).

## A07 — Identification and Authentication Failures

Clean.

- Authorization Code + PKCE (S256). No implicit, no hybrid, no ROPC, no device
  code — all disabled on the registration or blocked by policy.
- Authority pinned to one tenant; `tid` pinned **again** at claim validation, so
  the guarantee does not rest on a single configuration value.
- Principal keyed on `(oid, tid)` — never `upn` or `preferred_username`, which
  are mutable and reassignable.
- ID-token claims only. **The access token is never parsed**, per Microsoft's
  own checklist.
- Session fixation: a fresh identifier is minted at every callback.
- Pending flows are single-use and 5-minute TTL; `state` alone is not treated as
  a CSRF control, because a `state` the attacker chose is a `state` that matches.
- Session lifetime 8h absolute / 60m idle, deliberately inside a 4-hour
  Conditional Access sign-in frequency so CA governs, not this constant.

**Accepted limit, stated rather than claimed away:** sender-constrained tokens
(DPoP, mTLS, Entra PoP) are **not available** — MSAL's public-client PoP needs a
broker, and there is no broker in a Linux container. `doctor` asserts this
rather than assuming it. Compensating: in-memory-only tokens, `cp1` declared,
phishing-resistant MFA via CA, short session.

## A08 — Software and Data Integrity Failures

Clean, one item deferred.

- Digest-pinned base images; SHA-pinned actions; hash-pinned lockfile.
- Gitleaks scans full history; no secret exists to leak, which is precisely why
  an accidental commit would go unnoticed without it.
- **Deferred:** SBOM generation and image signing are documented in the
  Dockerfile but not produced by CI. Phase 6. Recorded so the deferral is a
  decision rather than an omission.

## A09 — Security Logging and Monitoring Failures

### OWASP-A09-01 — Refused authorisations left no trace. RESOLVED.
**Severity:** Medium
**Finding:** A sign-in refused for holding no DSAR app role, a token from the
wrong tenant, and a token with no `oid` all raised cleanly and logged **nothing**.
The only record that someone was turned away was the 403 they saw. One typo and
a hundred attempts were indistinguishable.
**Evidence:** probe — *"records emitted on a refused sign-in: 0"*,
*"records emitted on a wrong-tenant token: 0"*
**Reference:** OWASP Top 10 2021: A09 · CIS Controls v8: Control 8
**Resolution:** all three now log at WARNING with a `REFUSED` marker and the
`oid`, never the token. Regression tests for the first two.

**Already in place:** successful sign-in logs `oid`, roles and `uti` — the
per-token identifier that joins to Entra sign-in logs and Graph activity logs.
Request logging records the route *template*, so 401s and 403s are observable
without copying case identifiers into a second store.

### Open gap — no durable audit trail
**Phase 3 is not built.** There is no persistent record of who created which
case or ran which search; the evidence exists only in process logs, which do
not survive a container restart. For a tool whose value proposition includes
defensibility, this should not reach a customer engagement without being stated.
Not a regression — it was deferred deliberately to reach the demo — but it is
the largest remaining gap in this table.

## A10 — Server-Side Request Forgery

Clean.

- The Graph base URL is a constant. Every path comes from the operations table;
  no public method accepts a path, URL or endpoint argument, asserted by test.
- Path arguments are validated and, since SEC-H-02, cannot contain a dot-segment
  or percent-encoding.
- The Purview portal deep link is built from a fixed template with both
  components URL-quoted, and rendered as an `href` with `rel="noopener noreferrer"`.
  No `javascript:` or `data:` scheme can be produced from a case identifier.
- Redirects are constant (`/`) or built from a configured base URL — never from
  the `Host` header, which is caller input behind a proxy.

## Summary

Five findings across this pass, all resolved: one High (A01/A03), three Medium
(A04 ×2, A09), one Low (A01). **161 tests, `mypy --strict` clean.**

Three things carried forward rather than closed:

1. **No audit trail** (A09). The largest gap; deliberate, and should be declared.
2. **Authorisation is entirely Purview's** (A01). The right trade for a control
   plane, but it means this tool inherits whatever Purview's RBAC gets wrong.
3. **Hosted mode is unreviewed** (A01, A04, A07). The confidential client,
   federated credential and multi-operator sessions all land in Phase 5 and need
   their own pass.

One methodological note. Every finding in this document was found by **running
something** — fourteen strings through the path validator, sixty-nine requests
at a bounded store, a raising handler through the middleware stack. None was
found by re-reading code, and SEC-H-02 had survived two readings of the very
regex it defeated.
