**Artefact type:** Code + Architecture (container, CI, launchers)

## Pass 1 verdict: **Conditional approval**

No Critical and no High findings. The artefact's core security claims hold and
are enforced mechanically rather than by intention — the no-data-plane claim,
the absence of secrets, and the ban on token persistence are all asserted by
structural tests that were verified to fail when violated, not merely to pass.

Six Medium findings are raised. The two that matter most were confirmed by
probe rather than inspection: the audit directory is created group- and
world-readable (`0o775`), and a world-writable `config.json` is trusted to
supply the tenant and client ID that pin the authority. Both are defence-in-
depth failures on a shared host rather than remote exploitation paths, and both
are cheap to fix.

One structural gap is worth naming plainly: **request logging is disabled
outright** (`access_log=False`), which trades an OWASP A09 control for a
privacy concern that has a better answer.

## Medium findings

### SEC-M-01 — Audit directory created world-readable
**Severity:** Medium
**Location:** `src/dsar/doctor/checks.py` — `_check_audit_dir`, `target.mkdir(parents=True, exist_ok=True)`
**Finding:** The audit directory is created with the process umask, yielding `0o775` on a default Linux host. The audit trail is specified to carry operator `oid`/`upn`, tenant ID, case and search identifiers, and a case-scoped subject pseudonym. On a multi-user host any local account can read it. The design specifies `0600` for the audit *files* but nothing constrains the directory, and a directory another user can traverse and list defeats per-file permissions for enumeration purposes.
**Evidence:** Probe result — `mode: 0o775  group/other readable: True`
**Reference:** CIS Controls v8: Control 8 (Audit Log Management) · NIST CSF 2.0: PR.DS
**Resolution:** Create with `mode=0o700` and re-apply with `os.chmod` when the directory already exists, since `mkdir(exist_ok=True)` does not alter an existing directory's mode. Have `doctor` report the observed mode and fail when group or other bits are set.
**Verified by:** Re-running the probe; `doctor` output naming the mode; a unit test asserting `0o700` on both the created-fresh and pre-existing paths.

### SEC-M-02 — World-writable `config.json` is trusted to pin the authority
**Severity:** Medium
**Location:** `src/dsar/config.py` — `load_config`, the `config_file.is_file()` branch
**Finding:** `$DSAR_HOME/config.json` supplies `client_id` and `tenant_id`, and `tenant_id` builds `authority`. The file's permissions are not checked. A local attacker able to write it can redirect the operator to an attacker-controlled tenant and app registration; the sign-in page remains a genuine `login.microsoftonline.com` URL, so the operator has no visual cue, and a multi-tenant attacker application requesting `eDiscovery.ReadWrite.All` becomes a credible consent-phishing surface.
**Evidence:** Probe result — `world-writable config.json accepted: client=attacker-app tenant=attacker-tenant`, `authority: https://login.microsoftonline.com/attacker-tenant`
**Reference:** OWASP Top 10 2021: A05 — Security Misconfiguration · CIS Controls v8: Control 4
**Resolution:** Refuse to load a `config.json` that is group- or world-writable, naming the file and the required mode. Note honestly in the finding that an attacker with this level of access could also replace the `dsar` launcher — this is defence in depth, not a boundary.
**Verified by:** A unit test asserting `ConfigError` on a `0o666` and a `0o664` config file, and successful load at `0o600`/`0o644`.

### SEC-M-03 — Request logging disabled entirely
**Severity:** Medium
**Location:** `src/dsar/web/app.py` — `uvicorn.run(..., access_log=False)`
**Finding:** No request-level logging exists. The stated reason — request paths carry case identifiers — is a legitimate privacy concern, but the mitigation removes the control instead of narrowing it. Once Phase 1 lands, authentication failures, 401s and 403s will be unobservable from the application's own logs. Container Apps captures stdout, so the absence is a deliberate application decision rather than a platform gap.
**Reference:** OWASP Top 10 2021: A09 — Security Logging and Monitoring Failures · CIS Controls v8: Control 8
**Resolution:** Add a request-logging middleware that records method, **matched route template** (not the concrete path, so case identifiers never reach a log line), status code and duration. Keep `access_log=False` so uvicorn's own path-bearing logger stays off. The existing `RedactingFilter` remains attached as a backstop.
**Verified by:** A test asserting a request to a parameterised route logs the template and not the identifier.

### SEC-M-04 — Base images not pinned by digest
**Severity:** Medium
**Location:** `Dockerfile` lines 1 and 2 of each stage — `ghcr.io/astral-sh/uv:python3.13-bookworm-slim`, `python:3.13-slim`
**Finding:** Both base images are referenced by mutable tag. A tag can be repointed at a different image without any change to this repository, so the build is not reproducible and a compromised or altered upstream tag enters the supply chain silently. This matters more than usual here because reproducibility is the project's stated reason for existing.
**Reference:** OWASP Top 10 2021: A08 — Software and Data Integrity Failures · CIS Docker Benchmark: 4.7
**Resolution:** Pin both `FROM` lines by `@sha256:` digest, retaining the tag before the digest for human readability. Dependabot's `docker` ecosystem updates digest pins, so this does not freeze the images.
**Verified by:** `grep '@sha256:' Dockerfile` returning both stages; a rebuild producing the same base layers.

### SEC-M-05 — No repository secret scanning in CI
**Severity:** Medium
**Location:** `.github/workflows/ci.yml`
**Finding:** Trivy scans the built image for secrets, which catches material baked into a layer. Nothing scans the repository history or a pull request diff. The design has no secret to leak, which makes an accidental commit *more* likely to go unnoticed rather than less — there is no rotation process to trigger.
**Reference:** OWASP Top 10 2021: A02 — Cryptographic Failures · CIS Controls v8: Control 3
**Resolution:** Add a Gitleaks step to CI, SHA-pinned like every other action, with full history fetched (`fetch-depth: 0`) so history is scanned and not only the tip.
**Verified by:** The job appearing in CI and failing on a deliberately committed test credential.

### SEC-M-06 — Container filesystem is writable
**Severity:** Medium
**Location:** `dsar`, `dsar.ps1` — the `docker run` invocation
**Finding:** The container runs with a writable root filesystem. The application writes only to the audit directory, which is already a bind mount, so a read-only root costs nothing and removes the ability of an exploited process to persist to the image layer.
**Reference:** CIS Docker Benchmark: 5.12 · Azure Container Apps security baseline
**Resolution:** Add `--read-only` plus `--tmpfs /tmp:rw,noexec,nosuid,size=64m` to both launchers, and `--security-opt no-new-privileges` while there. Assert the flags in the launcher structural test alongside the existing loopback assertion.
**Verified by:** The container starting, serving and passing `doctor` with the flags applied; the structural test asserting their presence.

## Low and informational

- **[SEC-L-01]** `/healthz` returns the application version without authentication. In hosted mode this is an internet-facing endpoint and version disclosure assists CVE matching. — *OWASP A05* — Return the version only in desktop mode; hosted returns status alone.
- **[SEC-L-02]** `SECRET_SHAPED_ENV` covers three names and misses `DSAR_CLIENT_ASSERTION`, `AZURE_CLIENT_CERTIFICATE_PATH` and `*_PASSWORD`. The check is good; its coverage is narrower than its claim. — *CIS Controls v8: Control 3* — Broaden to a suffix match.
- **[SEC-L-03]** Response headers omit `Permissions-Policy`, `Cross-Origin-Opener-Policy` and `Cross-Origin-Resource-Policy`. COOP becomes materially relevant in Phase 1, when a browser redirect flow is introduced. — *MDN Web Security* — Add all three now rather than retrofitting after the auth flow exists.
- **[SEC-L-04]** Trivy runs with `ignore-unfixed: true`, so unfixable Critical and High CVEs in the base image are neither reported nor visible. — *OWASP A06* — Keep the blocking scan as-is and add a second non-blocking scan that reports unfixed findings, so they are seen without failing the build on something no patch exists for.
- **[SEC-I-01]** `origin_ok()`, `harden()` and `build_response_headers()` are defined but unused in Phase 0. Not security theatre today — they are scaffolding for the Phase 2 API — but an unused security helper that is never wired becomes theatre. Track the wiring.
- **[SEC-I-02]** No SBOM generation or image signing in CI. The Dockerfile comment documents `--sbom --provenance` for manual builds. Deferred to Phase 6 by plan; noted so the deferral is a decision rather than an omission.
- **[SEC-I-03]** Python dependency vulnerabilities are covered transitively — Trivy detects site-packages inside the built image. There is no separate lockfile scan, which is acceptable given every dependency reaches the image.

## Positive findings

Recorded because a review that only lists faults misrepresents the artefact.

- **The no-data-plane claim is enforced, not asserted.** The resource carrying the download permission is never named, by name or by application ID, and the scan was verified to fail when the string was reintroduced.
- **Structural tests were negative-tested.** Adding `dsar auth login` to the README produced `README.md:127` and a failing build — the exact line the predecessor shipped and nothing caught.
- **The scanner does not exempt itself.** Forbidden literals are assembled at runtime so no file needs excluding from the sweep. Four tests failed on first run against the author's own docstrings and the prose was reworded rather than exclusions added.
- **No hardcoded secrets, no `eval`/`exec`, no `pickle`, no `subprocess`, no SQL.** `sqlite3` is banned outright by test.
- **Container hygiene is sound:** multi-stage, non-root uid 10001 verified at runtime, `python:3.13-slim` minimal base, restrictive `.dockerignore` using deny-all-then-allow, `HEALTHCHECK` present, no secrets in layers.
- **CSP is `default-src 'none'`** with no `unsafe-inline` or `unsafe-eval`, and no duplicate headers were emitted — confirmed by probe.
- **Static serving uses an explicit allowlist**, not a directory mount; path traversal is not reachable because the served filename never derives from request input.
- **The bind-address invariant was relocated honestly** rather than quietly dropped when containerisation made the original guarantee false, with a test for each new location.

## Addendum — findings raised by CI after the pass-2 verdict

**Date:** 2026-08-14 · **Commit:** `4042ab5` · **Verdict unchanged: Approved**

Pass 2 was recorded before the image had ever been scanned in CI — the
container job had failed earlier on an unresolvable action pin, so the blocking
Trivy step never ran. On the first run that reached it, it reported **four
fixable High findings**. All four are now closed. Recorded here rather than
left in a CI log, because a finding that only exists in a job that has since
been re-run is not a record.

### SEC-H-01 — Starlette carries an SSRF and credential-theft vulnerability
**Severity:** High *(would have been blocking had it been found at pass 1)*
**Location:** `pyproject.toml` — `starlette>=0.42,<1`, resolving to 0.52.1
**Finding:** Two CVEs in the web framework, a direct dependency:
`CVE-2026-48818` — SSRF and NTLM credential theft via UNC paths (fixed 1.1.0),
and `CVE-2026-54283` — `request.form()` limits silently ignored (fixed 1.3.1).
The UNC issue matters more than usual for an application that will hold
delegated Graph tokens and run on a network where NTLM is reachable.
**Evidence:** Trivy on the built image — `starlette (METADATA) CVE-2026-48818 HIGH fixed 0.52.1 → 1.1.0`
**Reference:** OWASP Top 10 2021: A06 — Vulnerable and Outdated Components · CVE-2026-48818 · CVE-2026-54283
**Resolution:** Constraint raised to `>=1.3.1,<2` with the CVEs named in the
comment, so the floor reads as a security requirement rather than a version
preference. Resolves to 1.6.0.
**Verified by:** 85 tests pass and `mypy --strict` is clean on 1.6.0; Trivy
reports the package clean. The only side effect is a deprecation warning that
Starlette's test client prefers `httpx2` — test-only, not a runtime concern,
tracked but not acted on.

### SEC-M-07 — Package installer present in the runtime image
**Severity:** Medium
**Location:** `Dockerfile` runtime stage
**Finding:** `python:3.13-slim` ships pip, and pip's *vendored* tree carried the
other two findings — `msgpack` 1.1.2 (`GHSA-6v7p-g79w-8964`) and `setuptools`
70.3.0 (`CVE-2025-47273`, path traversal). Neither is a dependency this project
chose, so no change to `pyproject.toml` could fix them. Separately, a runtime
image that carries a package installer lets an exploited process fetch and
install code.
**Evidence:** `/usr/local/lib/python3.13/site-packages/pip/_vendor/` contains
both; `/app/.venv/bin/python -c "import pip"` already raised `ModuleNotFoundError`
before the change, confirming the application never needed it.
**Reference:** CIS Docker Benchmark: 4.3 (remove unnecessary packages) · OWASP Top 10 2021: A06
**Resolution:** Remove pip, its dist-info, `ensurepip` and the `pip*` console
scripts in the runtime stage, globbing the interpreter minor version so a base
image bump does not silently restore them.
**Verified by:** `importlib.util.find_spec("pip")` returns `None` in the image,
asserted by a new CI step; the container still builds, runs as uid 10001 under
a read-only root, both entry points agree and `doctor` passes.

### Residual, accepted

The report-only scan lists **23 unfixed findings, 4 of them Critical** — `perl`,
`ncurses`, `gzip` and related base-image packages with no available patch.
These are visible by design: SEC-L-04 split the scan precisely so that
unpatchable findings are known rather than suppressed. Failing the build on
something no patch exists for is not a control. Revisit at the Phase 6
distroless evaluation, which would remove most of this surface.

### Process note

The gate found a real vulnerability in a direct dependency on its first
execution, which is the argument for the gate. It also shows that a verdict
recorded before every check has actually run is a verdict with a hole in it —
pass 2 should have blocked on the container job completing rather than on the
remediation being written.

### Carried forward to the Phase 1 review

1. `origin_ok()` must be wired to the API surface, or removed (SEC-I-01).
2. ID-token claim validation must be ours, not assumed from MSAL: `tid` pinning,
   `roles` enforcement, and never parsing the access token.
3. The flow cache must be server-side, single-use and TTL-bounded.
4. `prompt=select_account` on the hosted authorize URL — its absence lets one
   operator inherit another's Entra session.
5. Audit records must exclude subject identifiers and KQL free text.
